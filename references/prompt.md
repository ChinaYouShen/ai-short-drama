# 提示词与模型

## MiniMax H3 路线与输出格式

接口硬限制（时长 4～15 整数秒、图片 ≤9、视频 ≤3、音频 ≤3、合计 ≤12、提示词 ≤7000 字符）、官方运镜词表与幅度速度写法、屏上文字、`[unclear]`、模型脾气与生成后核对，都在 [接口限制与词表](prompt.md)。本文件管路线与字段结构。

## 路线判定

| 用户选择 | H3 路线 | 参考素材在时间轴上的作用 |
| 文生视频 | T2VA | 没有作为依据的图、视频或音频，完整视听时间线由文字建立 |
| 图生视频·首帧 | I2VA | `<Picture 1>` 是 0.00 秒的硬首帧，后续动作从该画面自然开始 |
| 图生视频·尾帧 | L2VA | `<Picture 1>` 是视频结束时的硬尾帧，前段动作逐步收束到该画面 |
| 图生视频·首尾帧 | FL2VA | 首图锚定开始，尾图锚定结束，中间描述连续的状态变化路径 |
| 多参考生成 | Ref2VA | 图片、视频、音频分别提供身份、场景、动作、镜头、声音或风格依据 |
| 视频续接或编辑 | Ref2VA 或平台对应参考任务 | 视频本身被继续、修改或仅作参考，必须在 `summary` 中说明真实关系 |

若上游分镜对象使用 `t2v`、`i2v`、`l2v`、`fl2v`、`r2v`，分别映射到文生、首帧图生、尾帧图生、首尾帧图生和多参考生成。平台没有尾帧按钮时，不把 `l2v` 静默改成首尾帧。

首帧、尾帧和首尾帧是硬约束；普通人物图、风格图、动作参考视频和音色参考音频不是硬帧。用户说“参考这张图”时先确认它是硬帧还是普通参考，不能凭词语猜测。

## 结构化镜头输入

当上游已经提供分镜对象时，使用以下字段作为输入：

```text
mode: t2v | i2v | l2v | fl2v | r2v
beats: [{ start, end, text }]
durationSec: number
size: 景别
camera: 运镜
continuity: 衔接说明
linkPrev: boolean
dialogue: 原文对白
soundscape: 全程环境声
references: 按用户顺序排列的图、视频、音频清单
```

`beats`、`durationSec`、景别、运镜和衔接属于已确认的分镜设定。视频提示词负责把它们扩写成可执行描述，不负责重新拆镜或改变这些字段。`mode` 是可选路线；用户跳过时，不强制追问，不生成虚构的硬帧或素材标签，先交付不依赖路线的提示词正文。只有用户要求的输出格式无法脱离路线完成时，才询问该路线。

所有文戏和武戏镜头都读取 [镜头语言](prompt.md)。有角色出镜时使用近距构图，限制中景，禁止远景和大全景。

## 基础路线字段

T2VA、I2VA、L2VA、FL2VA 使用下面三个字段，字段顺序固定：

```text
integrated_multimodal_description:
[Shot 1] ...

overall_soundscape:
...

non_diegetic_music:
...
```

`integrated_multimodal_description` 沿时间顺序写视觉、主体、动作、表演、镜头、对白和镜头内声音。首帧路线在 `[Shot 1]` 开头说明它承接 `<Picture 1>`；尾帧路线在最后一个镜头明确落到图片状态；首尾帧路线说明首图、连续变化和尾图三者关系。

结构化结果中，`integrated_multimodal_description` 第一项只含整体风格，后续每项对应一个 `beats` 时间段，并包含 `shot`、`start`、`end`、`text`。最终 `prompt` 只由字段名、风格句、时间段正文和声音字段拼成，不包含 Markdown 标题或解释。

三种图生路线的开头或结尾约束分别是：

- I2VA：第一句说明 `<Picture 1>` 在 0.00 秒被完整承接，然后从图片中的姿态、构图、光线和道具继续发展。
- L2VA：最后一个镜头说明在视频结束时逐步收束到 `<Picture 1>` 的姿态、构图、光线和道具；不要把尾图误放成开场。
- FL2VA：说明 `<Picture 1>` 对齐 0.00 秒、`<Picture 2>` 对齐视频末秒，并描述两张图之间可执行的连续动作路径；除非用户明确要求，多数情况下使用一个连续镜头。

没有实际切镜时只写连续的 `[Shot 1]`，不为了套格式制造切点。确有切镜时，后续镜头使用递增时间，例如 `[Shot 2] At 00:04.200, the camera cuts to ...`。切点动词只用 `the camera cuts to`、`shot cuts to`、`shot transitions to`、`shot changes to`、`shot switches to` 五种；切点必须服务于新信息，轻微改变景别或角度优先用镜头运动表达，运镜按「类型＋幅度＋速度」写，见 [接口限制与词表](prompt.md)。

基础路线中的主体可以用稳定的角色名称或 `Subject` 说明，但只有 Ref2VA 需要完整的参考标签和保留分析。

### 时间码契约

提示词里每个 `At` 后的时间码只有一种合法写法：`mm:ss.mmm`，两位分、两位秒、三位毫秒。`00:1.200`、`00:001.200`、`00:03850` 都是错的，模型侧解析会失败或错位。

- 第一镜从 `00:00.000` 起写；也可以不写，此时第一个 `At` 代表第二镜的起点。
- 时间码必须严格递增，相邻两镜的差值就是镜长，必须落在 2～5 秒。
- 一个连续镜头不拆时间码；只有真硬切才增加 `[Shot N]` 与新的 `At`。
- 单段上限 15 秒（`SEGMENT_MAX_SECONDS`），**动作时长与台词时长合计算**，不是只算台词。
- 因此每段正文必须能核对总时长：在风格句处写「本段总长约 X 秒」，一段一句；多段输出时每段各写一次，各自 ≤15 秒。
- 超过 15 秒一律拆段，不靠删动作或加快语速硬塞：按「连续剧情多段输出」的规则承接，段末写稳定交接姿态，下一段从 `00:00.000` 重算。
- 最后一镜的结束点不写时间码，由「本段总长约 X 秒」与镜长共同约束。
- 四段结构（起势／宣言／爆发／收束）是时间预算，不是镜头数；段长不足 2 秒要与相邻段同镜，不切碎镜。
- 多段输出时每段各自从 `00:00.000` 重算，镜号也从 1 重起；这不是时间码倒退，脚本按段判。全篇只做一次递增判断会误报。
- 首镜可以不写 `At`（默认 `00:00.000`）；此时第一个 `At` 是第二镜起点，镜长按相邻切点连差推算，不从 0 秒重算。
- 切段只认正文时间线字段（`integrated_multimodal_description`／`detailed_description`／`详细描述`）。中文六段的 `主体定义`／`摘要`／`保留分析` 是段头，不构成新段起点；只有本段已经写完一次正文时间线，后续再出现正文字段才算下一段。



基础路线正文默认使用用户指定语言；用户未指定时跟随用户输入语言。Ref2VA 六段结构默认使用**英文字段名 + 中文正文**：字段键固定为 `subject_definitions:`、`summary:`、`retention_analysis:`、`detailed_description:`、`overall_soundscape:`、`non_diegetic_music:`，键后正文用简体中文。只有对白、歌词和画面文字按原语言写。技术标签、关系标记和 `<d>` 语言码始终英文。

只有用户明确要求「全中文标题」时才整体换成 `主体定义:`、`摘要:`、`保留分析:`、`详细描述:`、`整体声景:`、`非叙事配乐:`，且整篇统一、不与英文键混用。默认一律用英文字段名，结构化对象字段也始终使用英文键，避免不同解析器失败。

## 多参考路线六段结构

Ref2VA 使用以下六个字段，字段名和顺序固定：

```text
subject_definitions:
...

summary:
...

retention_analysis:
...

detailed_description:
...

...

...
```

### `subject_definitions`

为实际会进入成片或实际被引用的内容建立稳定标签：

- `<Subject N>`：人物、群体、道具、场景、服装、动作、姿态或视觉风格。
- `<Picture N>`：**只给真正承担首帧、尾帧、关键帧、分镜构图或时间轴锚点的图片**。只用来定义长相、服装、场景的纯来源图不单独建行，写进 `<Subject N>` 的定义里（`<Subject 1> is the woman in <Picture 1>`）；建了 `<Picture N>` 就必须写明它绑哪个 `<Subject N>`。
- `<Video N>`：被编辑、续接，或提供完整剪辑结构、节奏和镜头运动的视频。
- `<Audio N>`：被复制或参考的音频、音乐、音色、对白、歌词或声音质感。

每个标签只表示一个稳定含义，跨 `summary`、`retention_analysis`、`detailed_description` 和声音字段保持不变。一个素材可以提供多个主体，一个主体也可以由多个素材共同定义；只在实际使用时建立标签。

`<Subject N>` 只给**实际进入成片的对象**：人物、群体、道具、场景、服装、动作、姿态，或有素材支撑的视觉风格。「气质基调、光效语言、色彩倾向」这类没有对象承载的风格描述**不单独建号**——它没有主体，成片里也没有可指的实体，编号会凭空多出一号并让 `retention_analysis` 多出一行空账。风格写进 `summary` 一句，或写进 `detailed_description` 首句。只有用户真的挂了一张风格参考图、并要求锁定它的观感时，才把它登记为 `<Subject N>` 并在保留分析里标 `weak_reference`。

如果上游给出了参考素材清单，图片、视频和音频标签必须按清单顺序生成，数量不能少于清单中的实际引用，也不能凭空补号。图像类别固定为 `character`、`scene`、`prop`、`standing` 或 `reference`；视频使用 `<Video N>`，音频使用 `<Audio N>`。角色、场景、道具和站位的锁定范围不能互相替换。

#### 编号三套独立，绑定必须写明

`<Subject N>`、`<Picture N>`、`<Audio N>` 是三套互相独立的编号，不共用序号，也不默认一一对应。三张图两个角色、两个音色一个角色都是常态。

- **每个角色或主体都必须写清它用哪张图、哪段音频**，例如「月光（`<Subject 1>`）取 `<Picture 2>` 的外形、`<Audio 1>` 的音色」；不许因为「看起来是第一个」就默认配对。
- 编号一经按素材清单建立，全篇锁定：不中途改号、不重排、不在后文新增未登记的编号。
- 没有绑定音频的角色不写 `<Audio N>`；没有提供图片的主体不当作图像引用；用户只给了一张图时不推断还有别的图。

### 用户发来素材时怎么用（先清点，再判路线，再绑定）

用户上传图片或音频时，不要按张数硬套路线，也不要按上传顺序默认谁是谁。三步走：

**第一步：清点**（每张素材一行，缺项写「未指定」）

| 编号 | 类型 | 画面里是什么 | 用途 | 绑定谁 | 保留关系 |
| --- | --- | --- | --- | --- | --- |
| `<Picture 1>` | character | 深灰长衫中年男子半身 | 锁外形 | `<Subject 1>` | partially_preserved |
| `<Picture 2>` | character | 黑色短打年轻女子全身 | 锁外形 | `<Subject 2>` | partially_preserved |
| `<Picture 3>` | scene | 雨夜窄巷全景 | 锁空间与光位 | `<Subject 3>` | partially_preserved |
| `<Audio 1>` | voice | 低沉男声一句话 | 锁音色 | `<Subject 1>` 的声线 | reference |

模板见 [../templates/reference-manifest.md](../templates/reference-manifest.md)。

**第二步：判路线**（看这张图在时间轴上是不是硬帧，不看张数）

| 用户的实际情况 | 路线 | 判断依据 |
| 只有人物、场景设定图，要按描述演一段新动作 | Ref2VA | 图只锁外形与空间，不占时间轴 |
| 一张图，并说「从这个画面开始／接着这张动」 | I2VA | 这张图是 0.00 秒硬首帧 |
| 一张图，并说「最后停在这张」 | L2VA | 这张图是末秒硬尾帧 |
| 两张图，分别给了开头和结尾 | FL2VA | 首尾各一张硬帧，中间走连续路径 |
| 角色图 + 场景图 + 音色音频，要指定身份和声音 | Ref2VA | 各素材分别承担身份、空间、声音 |
| 给了一段视频要接着拍／要改里面的内容 | Ref2VA（`video continuation`／`video editing`） | 视频是源片，不是参考图 |

**路线优先级**：用户明确说了路线（「多参」／「首帧图生」／「首尾帧」）就按用户说的走，不能用素材推断去改判。用户说多参、而某张图恰好适合当首帧，这仍然走多参——图只锁外形与空间，时间线全部由正文生成。只有素材根本无法承担所选路线时（例如用户说首帧却只给了两张不同视角的设定图），先说明冲突、让用户选，不静默换路线。

**多参考不许写硬帧**：多参正文与 summary 里不得出现「首帧／尾帧／硬帧」，图只锁外形、服饰、空间与站位。要硬帧就改走 I2VA／L2VA／FL2VA 并在 summary 里写明。

数量不能替用户改路线；路线与素材作用冲突时先指出冲突，让用户选，不静默改成别的路线。

**第三步：绑定**（每张图、每段音频都要有一句话认领）

- 图片一律写「`<Subject 1>` 取 `<Picture 1>` 的外形／空间／站位」，同一行里两个编号都出现；脚本按这条硬规则拦（P20）。
- 音频写清三件事里的哪一种：**音色参考**（挂到某个 `<Subject N>` 的声线）、**对白复用**（整句沿用，`fully_copy`）、**配乐参考**（主题或节奏，`reference`）。每段音频都要在 `retention_analysis` 有一行账，脚本拦（P19）。
- 用户说「这个是他」但没说清是哪张图、对哪个角色时，先问一句再写；不许用「看起来第一张就是他」这种顺序推断。
- 用户只发了图没说要做什么（只参考外形／要当首帧），先按「只锁外形、走 Ref2VA」出一版，并在交付时把这个假设写出来。
- 同一素材支撑多个角色或同一角色由多张图共同定义时，把关系逐条写出，而不是靠编号顺序暗示。

### `summary`

用一个短段落说明任务和参考关系。按实际情况在开头使用以下任务类型并用 ` + ` 连接：

- `keyframe completion`
- `reference generation`
- `video editing`
- `video continuation`
- `audio reuse`
- `audio reference`

普通视频只提供镜头或动作参考时使用 `reference generation`；只有视频被直接改写才用 `video editing`；只有新内容从源视频末态继续才用 `video continuation`。原音轨完整沿用才用 `audio reuse`，只模仿音色、节奏或声音质感用 `audio reference`。

### `retention_analysis`

一行对应一个已定义标签，说明它出现在哪些镜头及其保留关系。可视内容使用：

- `fully_preserved`
- `partially_preserved`
- `attribute_transfer`
- `weak_reference`

音频使用：

- `fully_copy`
- `partially_copy`
- `reference`

关系描述必须与 `subject_definitions` 中的用途一致。新增剧情不算参考丢失；只有参考内容本身的使用方式发生变化才改变保留标记。

### `detailed_description`

先写整体视觉、空间和参考作用，再按播放顺序写镜头。每镜交代主体位置、动作或表演、镜头运动、状态变化和当前声音，并在第一次实际使用时插入对应参考标签。

连续镜头段仍只输出一个 `[Shot 1]`，本段时间从 `00:00.000` 重新计算；开头必须承接上一段末态并明确无硬切，结尾落在稳定交接姿态。只有确实发生硬切时才增加新的镜头编号。

## 连续剧情多段输出

用户明确要求把一条连续剧情拆成多段时，可以输出公共主体定义加多组提示词：

- 公共主体定义只锁一次身份、服装和长期参考关系。
- 每组只写当前段的摘要、保留分析、详细描述、整体声景和非叙事配乐；不重复建立角色档案。
- 第 2 组起保持同一空间、主体和配乐主题，详细描述首句写无硬切承接上一组。
- 每组时间从 `00:00.000` 重新起算，段末写稳定交接姿态；最后一组才收束动作或配乐。
- 用户选择严格改写时，只按用户给出的每段内容；选择允许扩写时，才补足段内镜头、声画和衔接细节。

## 台词、文字与声音

- **视频提示词正文不写角色姓名**：用通用身份指代（「一名铁灰长衫的中年男子」「对座的年轻女子」），姓名只允许出现在台词原文里。这是 H3 与同类视频模型的通行规范，不跟着提示词语言变。
- **分镜图提示词反过来要直呼其名**：那一侧的名字指向挂上去的那张角色设定图，用名字才能把图和人对上；两侧规矩不同，不要互相搬运。

- 说话者按首次发声顺序分配 `(S1)`、`(S2)`；同一人跨镜头沿用原编号。
- 说话者的身份、声线、语速和发声位置写在 `<d>` 外，实际台词只放进 `<d>[语言] 原文</d>`。
- **语言码写完整语言名**：`<d>[Chinese] 站住！</d>`、`<d>[English] Hold on.</d>`、`<d>[Cantonese] 唔好走</d>`。`zh`、`en`、`ja` 这类短码模型侧不认，等于没给语言码，脚本按违规拦下。
- 画外音使用 `says in an off-screen voiceover` 的语义，并紧跟说明画面内人物嘴唇保持闭合。
- 同一句话跨切镜时标出连续关系并使用 `<scenetrans>`；只有视频结尾确实截断发言时才用 `<cutoff>`。
- 台词、动作声和镜头内音乐写入当前镜头；连续环境声写入 `overall_soundscape`；角色听不到的配乐写入 `non_diegetic_music`。
- 画面中必须存在的字幕、招牌、界面或物件文字用双引号，并保持原始语言和标点。
- 分镜图提示词若被要求输出，应作为单独的 `framePrompt` 字段，只描述一个静帧，不写 H3 段名、时间轴或连续运镜。

## 参数与能力边界

官方 H3 文档的公开能力、输入数量、时长、比例、分辨率和平台按钮会更新。技能只根据用户当前选择生成结构，不把某次产品配置写成永远有效的保证。需要给出实际上传数量、API 参数或部署命令时，先以当前官方文档或用户界面为准。

### H3 官方口径与写作细则

本文件对齐 MiniMax 官方两套提示词指南（基础 T2VA/I2VA/FL2VA/L2VA 与全参考六段）、视频生成 V2 接口文档，以及两个开源短剧技能包里被反复验证的实操经验。生成前读一遍，交付前用 `scripts/validate.py` 过一遍。

### 一、硬限制（接口层，不是建议）

| 项 | MiniMax H3 | 备注 |
| 时长 | **4～15 秒，只接受整数** | 不是只能 5/10/15；8 秒、12 秒都合法 |
| 输出分辨率 | 768P / 2K | 2K 需走「视频再生成」 |
| 首/尾帧入口图片 | 0、1、2 张 | 0 张即文生视频 |
| 全能参考入口图片 | ≤ 9 张 | 与首尾帧互斥，不能混用入口 |
| 全能参考视频 | ≤ 3 段，单段 2～15 秒，总 ≤ 15 秒 | 只作结构或续接来源 |
| 全能参考音频 | ≤ 3 段，单段 2～15 秒，总 ≤ 15 秒 | 音色、对白、配乐 |
| 混合输入总数 | ≤ 12 个文件 | 图＋视频＋音频合计 |
| 提示词长度 | ≤ 7000 字符 | 超了会被截，台词容易丢 |
| 图片规格 | 边长 256～5760，宽高比 5:2～2:5 | 超范围直接失败 |
| 单文件体积 | 视频 50 MB、图片 30 MB、音频 15 MB | 只限单个素材 |

型号差异：**MiniMax-H3-Max** 为 5～15 秒、480P/768P，只支持文生与首尾帧，**不支持全能参考六段**。用户选了多参就别切到 Max。

换模型时槽位要重算：Seedance 2.5 可挂约 30 图 / 10 视频 / 10 音频、单次最长 30 秒；H3 只有 9 图 / 3 视频 / 3 音频 / 合计 12 个、最长 15 秒。同一份参考清单换到 H3，必须做减法而不是原样搬。反过来说，H3 的 15 秒上限意味着**一段只能讲清一个动作**，多节拍要拆段。

接口里的 `role` 语义：`first_frame`、`last_frame`、`reference_image`、`reference_video`、`reference_audio`；再生成任务额外加且仅加一个 `base_video`。

生成前想要更完整的措辞，可先调 **H3-Context-IR**：它只返回增强后的提示词、不建视频任务，但同样要求传 4～15 秒时长；拿到结果仍要核对逐字台词与时长容量。

### 二、运镜必须写成「类型 + 幅度 + 速度」

运镜不是标签，是镜头内的一句自然描述。官方词表：

| 意图 | 写法 | 变的是什么 |
| 变焦 | `Zoom In` / `Zoom Out` | 机位不动，焦距变 |
| 前后位移 | `Push In` / `Pull Out` | 机身向主体靠近或远离 |
| 左右平移 | `Truck Left` / `Truck Right` | 整机横向移动，不只是摇头 |
| 上下升降 | `Pedestal Up` / `Pedestal Down` | 整机升高或降低 |
| 原地转动 | `Pan Left` / `Pan Right` / `Tilt Up` / `Tilt Down` | 机身不动，镜头转 |
| 环绕 | `Arc Shot` | 绕主体走弧线 |
| 跟随 | `Tracking Shot` | 跟着移动主体走，保持关系 |
| 主观 | `POV` | 取主体所见 |
| 滚转 | `Roll Clockwise` / `Roll Counterclockwise` | 绕镜头轴转 |
| 不稳 | `Shake Slightly` / `Shake Strongly` | 受控晃动 |
| 不动 | `Static Shot` | 机位与焦距都不动 |

幅度只有两档：`with small amplitude`、`with large amplitude`。速度只有两档：`at slow speed`、`at fast speed`。**中等幅度与常速省略不写**。

```text
The camera pushes in with small amplitude at slow speed toward the folded letter in her hands.
The camera pans right with large amplitude at fast speed, revealing the open doorway.
The camera holds a static shot as the runner exits the frame.
```

中文正文里也照这个结构嵌英文短句，不要只写「镜头缓缓推进」「短弧环绕」——那类中文词模型只能猜。

### 三、切镜：五种动词，别为小变化切

- 切点动词只用这五个：`the camera cuts to`、`shot cuts to`、`shot transitions to`、`shot changes to`、`shot switches to`。交叉溶解、淡入淡出、划像只按用户明确要求使用。
- **切点必须带入新信息**：新主体、新空间、新状态、新视角或新时间。只换景别或轻微角度，一律用运镜解决。
- 首镜不写时间戳；后续写 `[Shot 2] At 00:03.500, ...`，切点严格递增且落在时长之内。
- 首尾帧任务通常一个连续镜头最稳：`[Shot 1]` 从 `Picture 1` 起，末段收束到 `Picture 2`。

### 四、台词、说话人与声音

- 说话人按实际发声顺序编号 `(S1)(S2)`，跨镜沿用；**不发声的角色不给编号**；两人齐说用 `(S1,S2)`。
- 身份、语气、动作写在 `<d>` 外，`<d>` 内只放语言标签与逐字台词：`(S1) 压低声音说：<d>[Chinese] 站住！</d>`。
- 画外音用固定短语 `says in an off-screen voiceover`，并在该 `<d>` 后紧接一句「画内角色嘴唇保持闭合」。同框有不说话的正脸时也要显式写闭嘴，否则口型容易落到近景不说话者身上。
- 同一句跨切镜：两段相接处都标 `<scenetrans>`，并写明声音跨切连续；只有视频结尾真的截断才用 `<cutoff>`。
- 复用的参考音频里听不清的片段写 `[unclear]`，不猜词、不改写；句末标点统一 `.`、`?`、`!`，去掉重复波浪号、表情与装饰符。
- 三层声音不混：
  - 镜头内同步声（台词、门响、画内收音机、角色弹奏）→ 正文时间线；
  - 全片环境与物理音（风、雨、脚步、布料、撞击、呼吸、喘息）→ `overall_soundscape`，1～4 句；不重复对白与音乐；
  - 只有观众听得到的配乐 → `non_diegetic_music`，1～3 句，只写乐器、速度、节奏、力度变化；**不许写抽象情绪词**，也不解释配乐在起什么情绪作用。
  - 无配乐写 `N/A`。省略这一层，模型会自己补一段音乐。

### 五、屏上文字

画面里必须出现的招牌、字幕、标签、界面、霓虹字，放进**英文双引号**并逐字保留原语言与原标点，不翻译、不改写：`A red neon sign above the door reads "开门" and stays unobstructed.`

### 六、全参考六段：标签怎么定

- `<Subject N>`：可复用的可见内容——人、物、场景、服装、道具、风格、动作、姿态、特效。
- `<Picture N>`：**只给真正当帧锚点的图**（首帧、尾帧、关键帧、分镜构图锚点）。
- **只用来定义长相、服装、场景的图，不单独建 `<Picture N>` 行**，把它写进 `<Subject N>` 的定义里：`<Subject 1> is the woman in <Picture 1>, with long dark hair and a blue cardigan.` 想让它当帧锚点，才另建一行。
- `<Video N>`：整段视频被剪辑、续接，或提供整片的镜头、切点、节奏结构。从视频里取出来的人或动作仍然是 Subject。
- `<Audio N>`：被复制或被参考的声音信号。参考视频本身带声音，不等于要建 Audio 标签；只有这段声音真的被复制或参考时才建。
- 一张图可以支撑多个 Subject；一个 Subject 也可以组合「图给外形 + 视频给动作 + 音频给音色」，逐项写明各自贡献。
- 编号在六段之间含义锁定，`summary` 里不新增未定义的标签。

`retention_analysis` 一行一个标签，并标注出现镜次：视觉用 `fully_preserved` / `partially_preserved` / `attribute_transfer` / `weak_reference`，音频用 `fully_copy` / `partially_copy` / `reference` / `weak_reference`。**这一节不写 `(Sx)`**——说话人编号只属于正文。

### 七、正文密度

官方给的参考是 **350～500 英文词**，这是信息量区间不是配额；对白密集的段优先把整条说话时间线写全。中文正文按同等信息量取 **350～550 字**，别为了凑字数灌形容词。

### 八、模型脾气（实操，不是官方条款）

- **文生偏真人**：非实拍画风（二维动画、三维 CG、黏土、水彩）在文生与首帧模式下容易滑向实拍。首句与每个 `[Shot N]` 开头都要声明媒介并排除 `realistic` / `photorealistic`；三维 CG 建议直接挂一张已定稿的画风起始帧走首帧模式。
- **首帧模式常忽略转身与出画方向**：要接戏的转身，先在起始帧把朝向摆出来，或多抽几张挑；还不行就在转身前切走。
- **只有场景图会拉宽景别**：没有起始帧时，场景图容易把镜头拉成远景。正文里要写清取景边界（例如「只拍到桌面与双手，不带到整间屋子」）。
- **近景与特写脸占画面大块时**：身份槽里只有全身板就加一张同造型的面部识别板，两图同时绑给同一个 Subject，保留分析里分工「五官发际」与「体态服装」。
- **首帧模式出声会延迟**：常见 1.3～2.4 秒才开口，排镜长要计入这段等待；纯等待镜头可在剪辑阶段剪掉。
- **两字呼喊容易漂**：单喊一个两三字的名字，发音常跑偏；画面允许时后期换音更稳。

### 九、脸和场景为什么会飘

换镜头就换脸、光色每镜不同、道具凭空消失，这三类问题不在提示词层解决，要回去修定妆图、空景板和分镜承接，见 [production/consistency.md](board.md)。

### 十、生成后核对这些

1. 身份：脸、发型、痣位、身高比例是否与参考一致；近景有没有换脸。
2. 服装与道具：版型、颜色、损伤状态是否延续到每个镜头。
3. 构图与落帧：首帧是否就是 `Picture 1`；首尾帧的最后是否真的落到 `Picture 2`。
4. 动作：起势、接触点、受力、落地是否按正文发生；有没有凭空多出的动作。
5. 台词：是否由正确的人开口、口型是否对上、有没有多念或漏念、画外音时画内嘴唇是否闭合。
6. 声音三层：环境声是否缺、配乐是否在没要求时自己冒出来。
7. 时长与切点：实际秒数是否等于声明的时长；切点位置是否与 `At` 一致。

### 十一、和官方口径的两处已知差异

- 官方两套指南写的是「六段正文用英文」；本包默认**英文字段名 + 中文正文**，因为中文创作者要直接读懂、直接改。结构、字段顺序、标签语义、保留标记与官方完全一致，只有叙述语言不同。要交给英文审稿或用英文接口时，把正文整体译成英文即可，不动标签。
- 官方 `overall_soundscape` / `non_diegetic_music` 建议 1～4 句 / 1～3 句英文。中文正文按句数对齐，不按词数凑。

### 跨模型对照：先查表，再写提示词

不同视频模型的时长、素材上限、是否原生出声差别很大。拿 15 秒的写法去套一个只收 8 秒的模型，整段会作废。写之前先查这张表，别凭记忆。

**口径会变**：档位与上限随官方调整，表里是常用档，落地前以你所用接口当日文档为准。

### 一、四家常用能力对照

### 二、换模型时改哪四处

1. **时长改整数档**：H3 写 12 秒可以，Veo 只能落到 8 秒或拆两段。换模型先重算镜头表，别只改一个数字。
2. **音频字段改位置**：H3 把环境声与配乐写在两个独立字段；Veo 与可灵有声版写在描述末尾的「声音指令」里。同一段话搬过去要重排，不能整段复制。
3. **素材上限重算**：H3 图 9、视频 3、音频 3、合计 12；Seedance 2.5 图 30、视频 10、音频 10。换到上限更紧的模型，先砍参考音频，再砍参考视频，最后才动角色设定图。
4. **结构重排**：H3 的六段字段搬进 Seedance 2.5 是无效的，必须改成四段式；反过来，Seedance 的四段也不能直接贴进 H3 的字段位。逻辑一样，容器不同。

### 三、写提示词的两条通用判据

- **一个「然后」就是两个镜头**。描述里出现「然后／接着／随后／紧接着」，说明一镜里塞了两件事，拆成两镜或两次生成。校验器 `P28` 会提示。
- **具象词胜过形容词**。「震撼、唯美、电影感」单独出现不产生约束；景别、运镜方向、光位、材质才产生约束。写「侧逆光、地面反光、镜头低角度贴地推进」，不写「画面很有张力」。

### 四、迁移检查

- 目标模型的时长档位与镜头表对得上吗？末镜有没有被压到 2 秒以下？
- 参考素材数量在目标模型上限内吗？超了先砍音频。
- 音频是按目标模型的字段写，还是照抄了别的模型的分栏？
- 出现「然后」的地方拆了吗？
- 替换掉的形容词，是否已经换成具体的景别、光位、运镜？

### 六、Seedance 2.5：四段式怎么写

H3 用字段容器，Seedance 2.5 用时间轴。同一份分镜换过去，不是换词，是换骨架。

**四段固定顺序：**

1. **素材绑定**：按上传顺序写清「这张图对应谁、参考它什么、不继承什么」。
2. **一句话概述**：主体 + 地点 + 事件 + 风格 + 一个特殊镜头，全片方向就这一句。
3. **整数秒时间轴**：`0–3 秒：动作 + 景别 + 运镜 + 声音`，按整秒切，不留空档。
4. **全局约束**：画幅、光线、色彩、机位稳定性，以及「无字幕、无 BGM」这类否定项。

**素材绑定三问，每张图都要答：**

- 对应谁：`@图片 1` 是人物 A 的外形，还是场景，还是只借光位；
- 参考什么：外形、服装、动作顺序、运镜节奏、音色，只选一项；
- 不继承什么：`@图片 1` 只管脸和衣服，不继承背景与姿势。

只写「参考图 1 是主角」，模型会连背景、构图、姿势一起抄进去。

**首尾帧：** 要精确的开头和结尾，走关键帧模式传首帧和尾帧，别在正文里描述「最后定格在……」。正文描述的首尾只是意图，模型按自己的理解落帧。只给首帧时，尾帧必须写成一个稳定的可见状态，不能写「然后转身离开」这种还在动的收尾。

**改片：** 三句话说全——改哪里（范围）、从什么改成什么、什么必须原样保留。「把表情改成惊讶」不合格；「只改 @视频 1 中人物的表情，构图、机位、光线、表演节奏全部保留」才合格。

**超过 30 秒：** 单次最长 30 秒，再长走延长链。每次延长从上一段的末态接，第一句写清承接的是哪个动作、哪个朝向，画幅比例锁死；不要每段重新描述人物长相，那会让脸重新采样。

**四个常见废片原因**（都能在写的时候避免）：

| 现象 | 原因 | 改法 |
| 人物换了张脸 | 素材没绑职责，模型自由发挥 | 补「对应谁 / 参考什么 / 不继承什么」 |
| 镜头之间各说各的 | 跳过一句话概述，没有全片锚点 | 先写一句「谁在哪干什么」 |
| 中段画面自己加戏 | 时间轴有空洞，模型补内容 | 时间轴按整秒铺满，不留缝 |
| 改一处连带全变 | 编辑指令没写保留项 | 范围 + 改动 + 保留，三样齐全 |

### 五、按镜头类型分派

一个项目不必全用同一家。把难镜交给它擅长的模型：

| 镜头类型 | 挑模型看什么 | 做法 |
| 人物近景、情绪特写 | 脸稳不稳、微表情 | 用最保脸的模型，一镜一句 |
| 动作与打斗 | 动作连贯、支持分段 | 切成 2 秒内碎片，优先支持首尾帧的 |
| 特效主体 | 能不能画出指定物体 | 只选明确写了主体还能画出来的，模糊描述必糊 |
| 大场面、群像 | 人数上限、空间稳定 | 先出静帧定构图，再让它照着动 |
| 转场、空镜 | 便宜、能批量 | 用低成本档，多出几条挑一条 |

换模型只换在镜与镜之间，不许一镜里混两家；换完重答那一镜的九问契约，不要只改模型名。

### 已有提示词优化流程

优化模式把用户现有提示词视为待维护的基线。先区分“事实错误”“H3 结构问题”“连续性问题”和“表达偏好”，再决定修改范围。

### 优化顺序

1. 标出必须保留的角色、对白、参考素材、动作顺序、结局、时长、比例、声音和禁项。
2. 判断当前文本属于 T2VA、I2VA、L2VA、FL2VA 还是 Ref2VA；发现字段混用先修结构。
3. 检查首帧或尾帧是否被误写成普通参考，检查参考标签是否稳定，检查人物和声音是否错绑。
4. 检查镜头时间、动作因果、文戏反应链或武戏接触链，优先修复会导致生成误解的问题。
5. 处理重复形容词、抽象情绪、堆叠运镜、过量特效和无法在时长内完成的内容。
6. 生成完整优化稿，再逐项核对没有改变未授权的故事事实。

如果用户给出结构化镜头对象，先把 `currentPrompt` 视为当前版本，把 `extra` 视为本轮修改范围。只更新用户点名的字段或段落；没有点名的对白、秒数、标签编号、素材顺序、分镜设定和结尾状态保持不变。除非用户明确要求，不输出新的 `beats`、分镜图提示词或其他镜头。

### 生成不了的四类写法

自查成稿里有没有下面四类写法，命中就改写。这不是审美偏好，是模型画不出来的东西：

- **否定式动作**：「没有接话」「没按下去」「不去看他」。画面生成不了没发生的事，必须换成正在发生的替代动作（把手缩回、把杯子推远、转身去擦桌子）。
- **不可见的内部状态**：「像是听见了什么」「神色一凛」「忽然明白过来」。换成可见的身体反应（眉头皱起、转头看向门口、手里的东西停在半空）。
- **精确拦截**：两人同时争夺一件小物、用手挡住正在合上的东西、运动中截住某物。这类要求双主体的时序和位置同时精确，会糊成一片；换成拦截的后果，或拆成两镜。
- **精细编排链**：一拍里串三步以上手部动作、左右手分工、单指操作小部件、厘米级位移。减到一两步，其余交给下一拍。

### 四条改写法（按顺序试）

1. **换承担者**：让物件或环境承担变化（门被风带上、杯子被碰倒、风把纸吹走），人只做反应。
2. **拆到相邻镜**：写成「动作前」和「结果」两镜，难生成的中间过程省略。
3. **换成停留**：把精细操作换成「做完之后手没有拿开」；情绪峰值仍要有可见的表情和身体变化，不能只靠停留。
4. **交给声音**：动作看不见时由已声明的声音承担（门闩响、瓷片落地、脚步停在门口）。

改写不得改变已确认的镜头边界、起止状态和剧情事实。唯一可行的改写会改变结果时，把冲突报给用户，不自行取舍。


### 修改边界

- 只优化用户选择的文戏或武戏部分；未选的另一戏型不被自动改写。
- 只优化用户选择的生成方式；需要换成另一种方式时先说明会改变输入约束，并让用户确认。
- 原有台词逐字保留，除非用户明确授权改词、翻译、增删或重新创作。
- 原有角色、人物关系、道具、空间和结局保留；补足的是表达路径，不是新剧情。
- 可把一条含混动作拆成起势、接触、反应和结果，但不能借拆分新增一次攻击或一次情绪转折。
- 可删除阻碍理解的重复词和无效镜头，但删除会改变剧情信息时列为待确认项。
- 用户提供的英文或其他语言提示词可以保持原语言；H3 字段名仍按格式文件固定，台词和画面文字保持原文。
- 参考素材清单是编号和类别的唯一依据。优化时不得因为补写画面而增加 `<Picture N>`、`<Video N>` 或 `<Audio N>`，不得把角色、场景、道具、站位的锁定作用互换。
- 连续镜头优化只沿用上一段末态和运动方向；本段时间仍从 `00:00.000` 起算，不把连续关系改写成首尾帧关系。

### 优化交付

完整交付包含：

```text
主要问题：...

优化后提示词：
<按选定 H3 路线的完整字段>

变更摘要：
- ...

文本检查：已检查结构、连续性和用户设定保留；未进行真实成片验证。
```

用户只要求可复制结果时，隐藏“主要问题”和“变更摘要”，只输出优化后的完整字段。用户只要求诊断时，只输出问题和修正建议，不伪造优化稿。

结构化输出至少保留原路线对应的完整字段和最终 `prompt`。如果用户只要求一段可复制文本，则隐藏内部对象和变更摘要，但不能隐藏路线字段导致基础三段与参考六段混用。

### 多段生产与拼接

单段提示词只解决「一段 4～15 秒怎么生成」。真正成片是若干段接起来，这一段最容易出问题：时间轴对不上、段与段之间差半秒黑帧、每段自带一份配乐导致拼接处音乐重影。

本文件只讲**多段**，单段的字段、镜长、特效仍按 [提示词主文件](prompt.md) 与 references/wuxi/validation.md。

### 一、两层时间轴，不要混

| 层 | 精度 | 作用 | 谁看 |
| 创作层 | 毫秒 | 镜头切点、动作峰值、台词起落 | 写提示词的人 |
| 生产层 | **整数秒** | 每段提交给模型的 `duration` | 接口与拼接脚本 |

规矩：

- 段内 `[Shot N] At MM:SS.mmm` 允许毫秒，按镜头需要写；
- **每段的声明时长必须是整数秒**（本段总长约 8 秒，不写 7.6 秒），因为它直接变成接口的时长参数；
- 多段连续时，段与段首尾相接：第 2 段从 0 起算自己的镜头时间码，但在全片时间轴上，它的起点等于第 1 段的终点，中间不留空、不重叠；
- 如果写了「全片总长约 X 秒」，各段声明时长之和必须等于 X，不留零头。

理由很实在：模型只收整数秒，你写 7.6 它也会被取整，声音和动作就在接缝处错位半秒。

### 二、拆段拆在哪

优先在自然断点上切，不要按「每 15 秒一刀」机械切：

1. 一句台词说完、换气之后；
2. 一次交手的命中之后、下一招起手之前；
3. 场景切换、时间跳转、视角换人；
4. 音乐或音效的明显转折处；
5. 情绪换挡处（压制转反打、追击转停顿）。

反过来，**不要切在**：台词说到一半、动作峰值上、镜头运动没走完、特效主体还没散干净的地方。

超过 15 秒必须拆；拆完每段各自 4～15 秒整数。末段不足 4 秒时，把前一段往前挪，重算边界，不要留一个孤零零的 2 秒尾巴。

### 三、接缝处怎么不跳

拼接最常出的三种毛病，各有对应写法：

| 毛病 | 原因 | 写法 |
| 黑帧闪一下 | 前段末尾多留了半秒空镜 | 末镜停在「动作刚完成、特效未散」那一帧，不留空 |
| 人物位置跳 | 两段的站位、朝向、光线对不上 | 每段开头写「承接上一段：人物在原位、光从同一侧来」，并沿用同一套服装与道具描述 |
| 特效断档 | 前段龙形还在，后段凭空消失 | 前段收尾写「开始塌缩」，后段开头写「余烬已散、只剩地面痕迹」 |

跨段的连续性靠台账记，不靠记忆：../../templates/continuity-ledger.md。

### 四、声音：一条主轨，别让每段自带配乐

多段拼接时最容易犯的错，是每段都写了完整配乐，拼起来音乐在接缝处重影。

规矩：

1. **每段只写本段的环境声与动作声**（雨声、脚步、破空、撞击），不写整段配乐；
2. 配乐单独一条主轨，成片时统一挂一次；
3. 需要音乐同步的地方（喊招落点、命中重音），在段内写「此处应有一记重音」，由主轨去对齐，不写「背景音乐响起」这种整体描述；
4. 拼接时先移除各段自带音轨，再挂主轨；不要靠叠加降音量糊过去。

台词也要单独记账：同一个人在跨段之间不能换音色，参考音频用同一段，见 ../../templates/reference-manifest.md。

### 五、提交前授权与幂等

生成接口按次计费，多段一次就是十几次调用，必须先做三件事：

1. **先授权再提交**：段数、每段时长、预计次数报给用户，得到明确同意才提交；不要默认「先跑一版看看」。
2. **幂等键**：每段用「项目名＋段号＋提示词哈希」做键，已成功的不重复提交。
3. **中断恢复**：失败或中断后按已保存的任务 ID 续跑，不要从头再来一遍。

这三条是防重复扣费，不是流程洁癖。

### 六、交付时给什么

多段成片交付，除了视频，附一张表：

| 段 | 整数时长 | 内容摘要 | 首帧承接 | 尾帧状态 |
| 1 | 8 | 雨夜巷战起手 | 无 | 对手贴墙、特效未散 |
| 2 | 10 | 反打与收势 | 承接 1 尾帧 | 掌印余温 |

这张表比任何说明都管用：下次要重做第 3 段，只看这一行就知道从哪接。

### 七、自查

- 每段声明时长是整数秒，且都在 4～15 之间；
- 写「全片总长约 X 秒」时，各段之和等于 X；
- 段与段之间无空档、无重叠，末段不少于 4 秒；
- 切点落在自然断点上，没有切在台词中间或动作峰值；
- 每段只写本段声音，配乐统一走主轨；
- 付费提交前有用户明确授权，且有幂等键与恢复方式。

### 景别与运镜

### 人物景别

- 只要人物或角色出现在画面中，禁止远景、大全景和远距离建立镜头，不把人物缩成环境中的小点。
- 人物镜头优先特写、近景、紧凑双人近景、过肩、主观视角和手部、眼神、道具等局部特写。
- 中景只在必须同时读清双人关系、关键肢体动作或位置变化时短暂使用；优先用近距离双人构图和连续局部镜头表达。
- 武戏保持人物与接触点可辨，优先紧凑双人近景、肩后跟拍、兵器或肢体接触特写、脚步局部特写。不得为了展示场地或完整队形拉成远景。
- 无人物的环境空镜可以使用较宽构图。需要交代地点时用空环境、前景细节、门窗局部或近景移焦，不在远景中放入人物建立空间。
- 用户已有分镜若含人物远景，按本规则收紧景别；保留招式、事件、关系和时间顺序。

### 景别和拍摄角度

按当前信息选择一项主要构图，不堆叠镜头术语：

- 对白与情绪：面部近景、反打近景、过肩近景、侧面双人近景、眼神或手部插入镜头。
- 多人交流：近距离过肩、前后景双人近景、逐人反应近景、焦点转换；保持人物方位和视线连续。
- 武戏交锋：紧凑双人构图、肩后跟随、兵器与接触点特写、重心或脚步特写、贴近主体的低机位或侧机位。
- 平视用于自然交流；低机位强调压迫或动作重量；高机位用于近距离观察姿势或受控局面；主观视角只在叙事明确绑定某人物时使用。
- 倾斜构图仅在失衡、眩晕或心理不稳确为表达目标时采用，不作为常规装饰。

### 运镜选择

### 焦距、景深与稳定性

景别决定「拍多大」，焦距决定「看起来像什么」，两项都要写：

- **广角（24–35mm）**：空间被拉开、边缘有轻微拉伸，适合狭窄室内交代两人距离；人物会显得离镜头更近，别用在脸上做特写。
- **标准（40–60mm）**：接近人眼，最不容易失真，默认用它。
- **中长焦（85–135mm）**：压缩空间、背景虚化成色块，适合把人物从杂乱环境里切出来、也适合暗处的压迫感。
- **景深**：浅（背景糊）、中浅、深（前后都清楚）。浅景深把注意力锁在脸上，深景深用来看清两个人同时的动作关系。
- **稳定性**分三档：稳定（三脚架感）、微晃（有人手持但稳）、手持（明显呼吸感）。稳定性和运镜分开写：「稳定机位 + 缓慢推近」和「手持 + 缓慢推近」是两种完全不同的片子。

每镜写哪几项、怎么写，见 [分镜](board.md) 的「构图要写满六项」。

每镜选择一个主要运镜，必要时附加一次焦点变化。每项都说明起始构图、移动方向、跟随对象和停止状态：

- 固定机位：让对白、微表情、动作线路或接触过程清晰可读。
- 缓慢推近：强化情绪、信息或攻击起势；停在近景或特写，不越过关键表演。
- 缓慢后移：只用于人物仍保持近距可辨的关系变化；不得退成远景。
- 横向滑轨或平移：揭示同一近距离空间中的另一人物、线索或动作结果。
- 跟拍或平摇：跟随人物、视线、兵器或移动目标；保持方向与主体连续。
- 俯仰跟随：沿人物起身、落下或兵器轨迹移动，不同时叠加无关旋转。
- 短弧环绕：从一个近距离角度绕向另一个角度，维持轴线和人物方位；不做无目的整圈旋转。
- 拉焦：在同一构图内把注意力从前景人物、对手、道具或动作接触点转向另一主体。
- 克制手持：仅用于明确需要临场感或失衡感的段落；保持主体、口型和动作接触点可辨，不用抖动掩盖信息。

文戏可用固定机位、缓推、横移、过肩反打和拉焦承接情绪或信息变化。武戏可用近距跟拍、短平摇、短弧环绕、接触点插入和动作匹配切展示攻防因果。一个镜头不同时安排推近、环绕、变焦、摇晃等多种主运镜。

### 连续性

- 运镜服务当前动作、表演或信息，不为展示技巧而移动。
- 相邻镜头维持人物左右、视线、动作方向、景别变化和空间轴线；改变方向时给出清楚的镜头过渡。
- 动作交锋先保证起势、接触或落空、反应和结果看得清；可用近距离局部镜头补足细节，不重复动作。
- 运镜与镜头时长匹配，完整对白、招式和反应不能被移动或切镜截断。
- 用户明确提供的景别或运镜按输入执行；人物远景除外，统一改为符合本规范的近距构图。

## 真人感六项：让画面不像塑料

写真人向提示词时，六项至少写四项，缺一项都会往「模型脸」偏：

| 项 | 怎么写 | 反例 |
| --- | --- | --- |
| 皮肤 | 毛孔、轻油光、局部泛红 | 磨皮、无瑕、发光 |
| 呼吸 | 胸口起伏、肩线随呼吸动 | 站定不动 |
| 微抖 | 手指、眼睑、发丝的小幅移动 | 完全静止 |
| 重心 | 起步先沉、落地先屈膝 | 平移滑行 |
| 眼神 | 先看物再抬眼，焦点落在具体位置 | 直视镜头、眼神空 |
| 环境互动 | 衣角被风带、脚印、手上沾灰 | 人和环境互不影响 |

六项不是形容词，要写成动作或可见细节；只写「真实感」「电影感」等于没写。

## 分镜译画面：把内部规划翻译成模型看得懂的句子

分镜表是给自己看的，提示词是给模型看的。中间必须翻译一次，否则模型照着自己的理解画。

**方位只用画面坐标**：画左、画右、前景、背景、朝向镜头、背对镜头、侧对镜头。不写东南西北，不写角度数字。

**不写内部编号和术语**：每段都用外貌称呼人物，「穿灰西装的中年男人」，不写角色号、事件号、阶段名。

**只写正面状态，不写否定句**：写「他双手空着垂在身侧」，不写「他没有拿插头」。否定句会让模型把被否定的东西画出来。

**一段只安排 2 到 3 个动作节拍**，时间按整秒写；不写 0.6 秒、1.6 秒这种细分时刻。

**把逻辑约束改写成画面**：不写「同一时刻只有一个身体」，写「他站在门口，手里拎着那只箱子」。

**不写环境人声**：每段只留很轻的底噪和真实动作声，人声统一在后期铺。

**台词三件事**：按 4.1 字/秒算字数；台词占比不超过这一段的 70%；每段最多两句；先说后做，说话时不做大动作。

**动作写次数，结尾写静止**：写「他拧了两下瓶盖，停住」，不写「他一直在拧」。段末必须停在一个可复现的姿势，否则模型会重复动作填满时长。

**道具一步到位**：每只手拿什么写清楚；关键交互单独给一个特写镜；道具从哪来到哪去，不在同一段里反复换手。

**站位给空间锚点**：人物相对固定物的位置（在门左侧、柜台前两步）；摄影机不换侧；人物换位要在镜头里演出来，不能靠下一镜直接站过去；隔着远的两个人用单人近景分别给。

**连续三段不要同景别同角度**：转折处换景别或推近，但不为了变化而切。

**每段记状态表**：谁在哪、每只手拿什么、道具在哪；下一段开头照抄上一段结尾的状态，不凭记忆。
