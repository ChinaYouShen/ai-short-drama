# 武戏生成流程

## 执行顺序

1. 确认本段目标：试探、压制、追击、反击、逃脱、救援、决胜、停战或继续交锋。
2. 锁定在场主体：身份、位置、朝向、距离、支撑、速度、高度、持有物、能力和当前状态。
3. 锁定动作载体：徒手、兵器、远程器械、能力、召唤物或环境借力。
4. 整理用户指定的招式名、流派、攻击目标、连招顺序、禁用动作和结束动作。
5. 建立招式序列：起势、轨迹、接触或落空、对手响应、受力、位移、下一状态。
6. 先容纳不可拆开的接触、落地、起身和完整台词，再分配镜头时间。
7. 为每镜确定主要观察目标、景别、机位、运镜、声音和结束状态。
8. 按选定的 H3 路线组装最终字段。

用户已经给出顺序时，严格保留。没有给出顺序时，使用：

`开场状态 → 试探或起手 → 首次攻防 → 拆招或反制 → 位移或换位 → 第二轮交锋 → 压制、反转或脱离 → 结果或下一段承接`

默认顺序不强制加入反转、终结、伤势、能力或新招式。用户只要求单招、短动作或一段续接时，只执行对应范围。

## 时长预算

先算账，再分镜。顺序反了就会出现「动作写了、时间放不下」的成稿。

1. 数出本段**必须完成**的接触次数：命中、格挡、落空、抓握、摔投、落地、起身各自算一次，不能合并成「连续攻击」。
2. 每次接触都要走完起势、接触、受力反馈、结果四拍；缺任何一拍，画面上就会变成模糊带过。
3. 按四拍所需时间累加，再加上完整台词、环境反应和收尾余波，得到本段的最小可行时长。
4. 最小可行时长超过用户给定的时长：先停下报告冲突，给出「减少招式数」「拆成两段」「延长时长」三个选项让用户选，不压缩动作细节硬塞进去，也不私自删用户的指定动作。
5. 用户没给时长时，用算出的最小值给一个建议时长，并说明是按几个接触动作推出来的。

## 没有静止表演

模型不具备「静止表演」能力：写成「对峙两秒」「蓄势待发」「悬停」「站立定格」的段落，生成出来就是角色呆立几秒、节奏拖沓。所以：

- **蓄力和对峙一律挂在运动上**：边打边蓄、上升途中蓄、后撤中蓄、绕步中蓄；神态挂在动作瞬间（甩剑转身时冷笑、格挡瞬间抬眼），不单独成段。
- **唯一允许的定格**是命中瞬间 1～2 帧的微停顿（用来让观众看清这一下打实了），其余静止段不用。
- **同一种节奏连续不超过 5 秒**：密集连打之后用一个重击、一次位移或一个环境反应换挡，节奏才有呼吸。
- **开局要快出接触**：写实克制档（格斗、暗杀、追逐）不强制，但 1.5 秒内要发生第一次攻防接触；强对抗档在开场 0.5 秒内就给出一次硬碰。第一帧用双人同框中近景，不用远景慢热铺垫。
- **收尾停在最高点**：强对抗档的最后一帧停在命中、失衡、冲击或倒地的那一刻；只有写实克制档允许克制收势或留悬念。
- 不用慢镜、升格来替代节奏变化；需要强调某一击时只给这一击，并写明慢放的起止时刻。

## 动作记录

每个招式先形成一条动作记录，再写入镜头：

`order`：顺序号；`actor`：发起者；`target`：目标；`move`：招式名或可见动作；`setup`：站姿、重心、握法和进入路线；`trajectory`：攻击、格挡、闪避、抓握、摔投或能力线路；`contact`：命中、格挡、擦过、落空、锁控或作用终点；`response`：目标响应；`result`：受力、位移、姿态、持物和环境结果；`next`：下一招起点。

后一条记录只能使用前一条记录的 `result`，不能恢复开场姿态。每条记录只执行一次，不用“连续攻击”代替具体过程。

## 选取边界

- 用户指定招式名时保留名称，并写出可见执行过程。
- 用户未指定招式名时写中性动作，不擅自套用流派名称。
- 用户要求创作招式名时，招式名只作动作标识，不自动成为对白、能力或胜负宣告。
- 用户指定流派时只使用该体系能成立的站姿、步法、发力和节奏，不混入互斥体系。
- 用户指定流派但拿不准该体系的具体术语和动作语汇时，用通用动作语言写，不编造流派招式名、口诀或师承细节来充数。
- 动作装不下时指出时长冲突，请用户选择拆段、延长或减少招式，不自行改序。
