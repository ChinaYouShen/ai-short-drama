## 可选设计参数

- `动作载体`：徒手、兵器、能力、位移、混合。
- `战斗人数`：单组交锋、多人交锋。
- `分镜方式`：单镜完成、多镜连续、续接上一段。

用户已明确的选项直接沿用。信息足以完成当前请求时不追问；只有缺失内容会改变动作因果或结果时，才提供简短选择。用户还可以指定目标、招式名、流派、兵器、能力、时长、结果和禁用动作。

### 武戏生成流程

### 执行顺序

1. 确认本段目标：试探、压制、追击、反击、逃脱、救援、决胜、停战或继续交锋。
2. 锁定在场主体：身份、位置、朝向、距离、支撑、速度、高度、持有物、能力和当前状态。
3. 锁定动作载体：徒手、兵器、远程器械、能力、召唤物或环境借力。
4. 整理用户指定的招式名、流派、攻击目标、连招顺序、禁用动作和结束动作。
5. 建立招式序列：起势、轨迹、接触或落空、对手响应、受力、位移、下一状态。
6. 先容纳不可拆开的接触、落地、起身和完整台词，再分配镜头时间。
7. 为每镜确定主要观察目标、景别、机位、运镜、声音和结束状态。
8. 按选定的 H3 路线组装最终字段。

用户已经给出顺序时，严格保留。没有给出顺序时，使用：

`开场状态 → 试探或起手 → 首次攻防 → 拆招或反制 → 位移或换位 → 第二轮交锋 → 压制、反转或脱离 → 结果或下一段承接`

默认顺序不强制加入反转、终结、伤势、能力或新招式。用户只要求单招、短动作或一段续接时，只执行对应范围。

### 时长预算

先算账，再分镜。顺序反了就会出现「动作写了、时间放不下」的成稿。

1. 数出本段**必须完成**的接触次数：命中、格挡、落空、抓握、摔投、落地、起身各自算一次，不能合并成「连续攻击」。
2. 每次接触都要走完起势、接触、受力反馈、结果四拍；缺任何一拍，画面上就会变成模糊带过。
3. 按四拍所需时间累加，再加上完整台词、环境反应和收尾余波，得到本段的最小可行时长。
4. 最小可行时长超过用户给定的时长：先停下报告冲突，给出「减少招式数」「拆成两段」「延长时长」三个选项让用户选，不压缩动作细节硬塞进去，也不私自删用户的指定动作。
5. 用户没给时长时，用算出的最小值给一个建议时长，并说明是按几个接触动作推出来的。

### 没有静止表演

模型不具备「静止表演」能力：写成「对峙两秒」「蓄势待发」「悬停」「站立定格」的段落，生成出来就是角色呆立几秒、节奏拖沓。所以：

- **蓄力和对峙一律挂在运动上**：边打边蓄、上升途中蓄、后撤中蓄、绕步中蓄；神态挂在动作瞬间（甩剑转身时冷笑、格挡瞬间抬眼），不单独成段。
- **唯一允许的定格**是命中瞬间 1～2 帧的微停顿（用来让观众看清这一下打实了），其余静止段不用。
- **同一种节奏连续不超过 5 秒**：密集连打之后用一个重击、一次位移或一个环境反应换挡，节奏才有呼吸。
- **开局要快出接触**：写实克制档（格斗、暗杀、追逐）不强制，但 1.5 秒内要发生第一次攻防接触；强对抗档在开场 0.5 秒内就给出一次硬碰。第一帧用双人同框中近景，不用远景慢热铺垫。
- **收尾停在最高点**：强对抗档的最后一帧停在命中、失衡、冲击或倒地的那一刻；只有写实克制档允许克制收势或留悬念。
- 不用慢镜、升格来替代节奏变化；需要强调某一击时只给这一击，并写明慢放的起止时刻。

### 动作记录

每个招式先形成一条动作记录，再写入镜头：

`order`：顺序号；`actor`：发起者；`target`：目标；`move`：招式名或可见动作；`setup`：站姿、重心、握法和进入路线；`trajectory`：攻击、格挡、闪避、抓握、摔投或能力线路；`contact`：命中、格挡、擦过、落空、锁控或作用终点；`response`：目标响应；`result`：受力、位移、姿态、持物和环境结果；`next`：下一招起点。

后一条记录只能使用前一条记录的 `result`，不能恢复开场姿态。每条记录只执行一次，不用“连续攻击”代替具体过程。

### 选取边界

- 用户指定招式名时保留名称，并写出可见执行过程。
- 用户未指定招式名时写中性动作，不擅自套用流派名称。
- 用户要求创作招式名时，招式名只作动作标识，不自动成为对白、能力或胜负宣告。
- 用户指定流派时只使用该体系能成立的站姿、步法、发力和节奏，不混入互斥体系。
- 用户指定流派但拿不准该体系的具体术语和动作语汇时，用通用动作语言写，不编造流派招式名、口诀或师承细节来充数。
- 动作装不下时指出时长冲突，请用户选择拆段、延长或减少招式，不自行改序。

### 动作的可生成性

写武戏最容易出的问题不是招式不够花，而是写了模型拍不出来的动作。这一份只管「能不能拍成」，不管招式设计。招式设计读 [flow.md](rules.md)，分镜读 [basics.md](basics.md)。

### 一、优先写高频、整体、单部位能完成的动作

| 可直接写 | 需要改写 | 为什么 |
| 走进、坐下、起身、回头、点头、递物、接过、抱住、推门、放桌面、翻页、伸手去够 | 用工具挡住运动中的物体、厘米级位移、单指拧微小部件、四步以上双手编排、只靠微表情承重 | 前者高频、整体、单躯干或单臂即可完成；后者要求多部位同时精确对位 |

### 二、四类必须改写的高风险写法

1. **精确拦截**：两人同时争夺同一个小物、用手掌挡住正在合上的东西、运动中截住飞行物。要求双主体的时序与位置同时精确，几乎必崩。
2. **不可见的内部状态**：「像是听见了什么」「神色一凛」「忽然明白过来」。改写为可见表情与身体动作：「眉头猛地皱起，转头看向门口」。
3. **否定式动作**：「没有接话」「没有按下去」「不去看他」。画面生成不了「没发生的事」，改写成正在发生的替代动作。
4. **精细编排链**：一拍内串起三步以上手部动作或左右手分工。

### 三、改写方法，按顺序试

1. **换承担者**：让物件或环境承担变化——「门被风带上」替代「他用脚勾住门」。
2. **拆到相邻镜**：拆成「动作前」（笔停在纸上）与「结果」（纸上多了一行字），略掉难生成的过程。
3. **换成停留**：把精细操作换成「做完后手没有拿开」。停留只替换精细操作，情绪峰值仍要有可见表情与身体变化。
4. **交给声音**：动作不可见时由已声明声源承担（门被撞开的巨响由 `overall_soundscape` 交代）。
5. **标注高风险与降级方案**：确实无法替代时，在镜头说明里注明高风险，并给一个可接受的降级实现。

改写不得改变已确认的镜头边界、起止状态与剧情结果；若唯一可行的改写会改变结果，先说明再让用户定。

### 四、打斗与身体接触

**一时段只有一个主体出手。** 按回合分时写，每段只写一个人的发力路线，另一段写承受者顺着来力的反应：

```text
0～1.5 秒 他抡起木棍朝对方头顶劈下；
1.5～3 秒 对方上身朝自己右侧一偏，木棍擦着左肩落空。
```

双主体同时发力就是精确拦截，做不成。交锋咬合的画面靠剪辑在动作中途切换，不指望一次生成完成。

- **左右按人物自身写，不按画左画右**：写「他的右拳」「朝集装箱一侧偏身」。机位一换，画左画右就翻，按画面方位写必然穿帮。
- **写路线与反应，不写接触点形变**：写「右拳从镜头前方朝他下巴方向挥过，他的头猛地朝左甩开，踉跄后退两步」，不写「拳头打在脸上、脸被打得变形」。
- **贴身控制写两态**：先说清谁的哪只手臂箍住谁的哪里，再说松开或放倒；中间不写多步换手。
- **慢动作只给决定性一击**，并写明起止时刻；其余变速留给剪辑。
- **打击特写单独成段**：画面只写承受者，拳脚从画外闯入，头顺来力甩开，飞溅物（雨水、汗、尘）与镜头震动写在这一段；段与段之间写「切到」，不写连续运镜。
- 兵器在每镜的**起点与终点各在谁手里**都要写清；脱手要有落点，不能中途凭空换手。

### 五、固定机位必须写满三件事

写「固定机位」四个字等于什么都没说，执行端会自由漂移。必须写：

1. **固定构图**：景别、机位高度、轴线在哪一侧；
2. **画面里唯一在动的表演与环境元素**；
3. **保持时长**：「保持约两秒半不动」。

例：「固定特写，俯拍，轴线左侧，取她的头肩；画面内只有她的呼吸和身后帘子在动；保持约两秒半不动。」

### 六、同一时段不许指令打架

同一时间段里不能既写固定机位又写推近、跟随，也不能无过渡地先左摇再右摇。先静后动要写成不重叠的分段：

```text
0.0～1.2 秒 固定机位：等他抬眼；
1.2～4.0 秒 缓慢推近：从双人中景收至他的头肩近景，终点保持在既定轴线。
```

### 七、交付前自查

- 有没有一段里两个人同时发力？
- 有没有写「挡住」「截住」「捏住指尖」这类精确对位？
- 有没有用「神色一变」「似乎察觉」交代内心？
- 有没有「没有动」「没接话」这类否定式动作？
- 每一个「固定机位」是否三件事都写满了？
- 兵器每镜首尾是否都在明确的一只手里？
- 打斗镜的左右是不是按人物自身写的？

### 动作导演：因果、状态与配速

招式参数表解决「这一招长什么样」，这一份解决「两招之间为什么成立」。缺了这层，提示词里每个动作都好看，连起来却像各打各的。

配套：[vfx.md](vfx.md) 特效主体规范、[镜头语言](../prompt.md) 景别与运镜、[分镜](../board.md) 分镜排版。

### 一、每个参战角色先建动作档案

八项，缺一项就会在交手里露出破绽：

| # | 项 | 要写到什么程度 | 例（降龙掌使用者） |
| 1 | 优势距离 | 几米内最强 | 一米内贴身，一步外靠掌风 |
| 2 | 起手姿态 | 开打前身体怎么摆 | 左脚前虚点、右掌贴腰 |
| 3 | 移动方式 | 步法特征 | 直线抢中，少侧绕 |
| 4 | 主要攻击方式 | 靠什么打 | 双掌推、肩撞 |
| 5 | 防守与反制习惯 | 挨打后怎么回 | 卸力半步、立即反推 |
| 6 | 资源 | 兵器、弹药、内力 | 内力有限，三掌后要换气 |
| 7 | 力量节奏 | 快慢如何起伏 | 两慢一快，第三掌最重 |
| 8 | 结束战斗的方式 | 靠什么收 | 一掌定身，不追打 |

两个角色至少在**优势距离、移动方式、反制习惯**三项上明显不同；三项都一样，打起来就是自己打自己。远程角色要写视线与弹道，近战角色要写怎么缩短距离，体型差要落在速度与受力上。

### 二、每轮交锋写六项

一次交锋＝一个可读的攻防单元。六项齐全才算「有因果」：

1. 谁发起；
2. 动作指向哪里（部位、方向）；
3. 接触、格挡还是落空；
4. 对方怎么回应；
5. 双方位置怎么变；
6. 什么状态支撑下一拍（距离、失衡、遮挡、资源、场景损伤、暴露的空当）。

反例：两人同时出招、各打各的、镜头一换又都站回原位。这类写法在视频里读不出胜负，观众只觉得乱。

**命中必须给结果**：加速方向、接触点、受力方向、位移终点、环境反馈（水花、尘土、砖裂、雨线断开）。同一次命中的环境变化，要在后面镜头里留着。

### 三、跨镜不重置的四样

切镜之后自动复原，是打戏最常见的崩坏：

| 状态 | 要延续什么 |
| --- | --- |
| 位置 | 上一镜结束时双方在哪、朝向谁 |
| 兵器 | 是否脱手、断口在哪、刃口朝哪 |
| 损伤 | 谁身上哪处有伤、血往哪流、衣服哪块破了 |
| 场景 | 已碎的物件不会复原，已塌的墙不会立回 |

写下一镜开头一句「承接上一镜：他退到墙根、刀在左脚边」，比任何解释都有效。

### 四、配速预算：两个档位，不靠形容词

**强度与速度是两条独立的轴**，不要混成一个「很猛」。强度管动作多大，速度管切多快。

以 15 秒段为单位：

| 档 | 段数 | 每段 | 交锋次数 | 微动作 | 镜头数 |
| 标准 | 4 段 | 3～4 秒 | 高强度 6～8／中间 5～7／慢 4～6 | 12～18 | 高强度 6～8／中间 5～7／慢 3～4 |
| 极速 | 5～6 段 | 2～3 秒 | 高强度 7～9／中间 6～8／慢 5～7 | 16～22／12～16／10～14 | 高强度 6～9／中间 5～7／慢 3～4 |

极速档的三条硬规矩：

- 第一个有效动作不晚于 0.15 秒出现（标准档 0.3 秒）；
- 纯走位或纯恢复动作不超过 0.3 秒（标准档 0.7 秒）；
- 极速档默认不用慢动作；决定性命中要看清楚时，全片只留一次，0.15～0.3 秒。

**注意本包的口径**：H3 单镜下限是 2 秒（见 [自检清单](validation.md) P7）。所以极速档不是靠切更碎的镜头，而是靠**段更短、镜内动作更密**。想切 0.5 秒的特写，只能放在多段结构里去拆段，不能压单镜时长。

时长与结构的对应：

| 时长 | 装什么 |
| --- | --- |
| 4～8 秒 | 一个完整动作闭环，最多一次明显转折 |
| 9～18 秒 | 起动、争夺、反制、结果四到五阶段 |
| 19～30 秒 | 五到七段，中段安排一次有效反转 |

### 五、重击与终结技

- 重击必须有**可见起势**：重心下沉、脚步压地、兵器后引、光形收缩，四样里至少两样；
- 终结技多一道流程：触发 → 蓄力 → 锁定目标 → 释放 → 结果，五步都要有画面；
- 普通交手可以快，终结技不能省步骤，省了就变成「莫名其妙赢了」。

### 六、参考素材按职责分工

一份素材只干一件事，别让它同时管身份、场景、动作和镜头：

| 素材 | 只管 |
| --- | --- |
| 角色图 | 外观 |
| 场景图 | 环境 |
| 站位图／首帧 | 第 0 帧谁在哪、朝哪 |
| 轨迹图 | 后续路线 |
| 动作参考视频 | 身体轨迹、力量方式、节奏 |
| 运镜参考视频 | 机位、路径、速度 |

用户最新的一条明确指令永远优先。素材编号属于沟通，**不写进生成正文**（正文留空或只写「见附图」）。

### 七、交付：净稿与面板分开

实测反复出现同一个问题：把编号、时长预估、检查点、自检表混在正文里，拿去生成就会一起被喂进模型。

规矩：

1. 交付文件分两段：**可复制正文**（只有场景、动作、台词、声音）+ **节奏调整面板**（段长、镜数、待改项）；
2. 面板明确标注「不进生成」；
3. 正文里不出现「自检」「检查点」「预估 90.8 秒」「【本集结算】」这类工作痕迹；
4. 校验器 `P29` 会在正文里发现这些词时提示。

### 八、失败修正：一次只改一类

打戏出问题的三类变量：**动作、镜头、素材**。每轮只动一类，改完重新生成再判断。

| 症状 | 先改哪类 |
| --- | --- |
| 看不出谁打谁 | 镜头（换一个能看清接触的角度） |
| 动作软、没力量 | 动作（补起势与受力结果） |
| 人物脸崩、服装乱 | 素材（补角色图或换更近的参考） |
| 特效糊成一片 | 动作（把特效主体改成可画形状，见 vfx.md） |

一次改两类以上，出了问题无法归因。

### 九、自查

- 每个角色八项档案齐了吗？三人以上有没有两项以上同质？
- 每轮交锋六项齐吗？有没有「同时出招、各打各的」？
- 命中写了受力结果吗？环境变化延续到下一镜了吗？
- 切镜后位置、兵器、损伤、场景是否保留？
- 段数、交锋次数、镜头数落在所选档位预算内吗？慢动作是否只留一次？
- 重击有起势吗？终结技五步齐吗？
- 每份素材只担一个职责吗？素材编号是否留在正文外？
- 交付正文里还有工作痕迹吗？

### 武戏连续性

跨镜或跨段时，至少继承以下状态：

- 相对位置和画面方位
- 身体朝向、速度和高度
- 支撑、姿态和受力方向
- 武器类型、数量、持握手和损坏状态
- 伤势、体力和能力残留
- 环境物件的完整度、碎片、尘雾和运动方向

状态改变必须由动作、接触、位移、转场或用户明确设定触发。切镜不能让角色自动复位、换手、恢复完整或改变目标。

### 武戏声音

声音与动作事件绑定：脚步、衣料、兵器挥动、接触、落地、喘息、环境反应和现场音乐写入当前镜头或 `overall_soundscape`；角色听不到的配乐写入 `non_diegetic_music`。

撞击声只在接触或结果出现时发生。没有兵器接触时不写金属碰撞；没有用户要求时不补喊招、痛呼、骨裂声、爆炸声或致命后果。

参考音频只约束用户指定的音色或节奏，不复制其中未被用户提供的台词。
