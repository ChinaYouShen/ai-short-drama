# 武戏基础：招式载体、分镜与承接

## 招式模块索引

只读取用户选择的动作载体模块。混合载体只加载实际参与本段的模块，不加载全部模块。

| 动作载体 | 模块 | 核心字段 |
| --- | --- | --- |
| 徒手 | unarmed.md | 站姿、支撑、出手、接触、回收 |
| 兵器 | weapon.md | 握持、兵器部位、线路、接触、收回 |
| 能力 | ability.md | 前置、产生、传播、作用、终止 |
| 位移或轻功 | movement.md | 动力、支点、路径、落点、承接 |

每个模块只负责动作执行，不负责分镜字段、声音字段或其他模块的动作。招式序列统一由 ../flow.md 管理。

带名字、有喊招、有法相或场域的大招不按本表选模块，改走 [vfx.md](vfx.md)：那里按攻击形态分成五种范式，再回到对应载体补身体路径。

## 选定前的可执行性核对

写入分镜前，先对每一个准备使用的招式逐条过一遍，有一项明显不成立就换动作或说明冲突，不硬写：

1. **能力匹配**：这个角色会这个招式吗？不会就要有学会、借力或临时爆发的可见理由。
2. **器械与肢体的兼容**：兵器形制、长度、双手或单手、以及角色的身体条件（身高、伤残、年龄）能不能支撑这个动作。
3. **入口姿态**：能不能从上一动作结束时的姿态直接进入？需要先撤步、收兵、换手或起身时，把这段过程写出来。
4. **空间条件**：当前场景有没有这个动作需要的距离、支撑点、落点、遮挡物和可破坏物；没有就换招或换位置。
5. **时长余量**：在用户给定的时长内，起势、接触、受力反馈和结果这四段放得下吗；放不下先报告，请用户选择缩短、拆分或换招。
6. **红线一致**：有没有违背用户锁定的动作顺序、胜负、禁用动作或写实程度；发现冲突就回到用户确认，不为保留招式去改剧情。

核对通过后，再把身体路径、接触部位和结果写具体；核对不通过时，宁可换一个更朴素但成立的动作，也不用看起来花哨却进不去、接不上的招式。

### 徒手招式

每次徒手动作写清支撑脚、重心、身体朝向、出手部位、攻击或控制线路、接触部位、对手反应和回收姿态。

### 基本顺序

`站稳或移动 → 进入距离 → 起手 → 出手或控制 → 接触或落空 → 受力反馈 → 回收、追击或脱离`

拳、掌、肘、膝、腿、擒拿和摔投都要落成可见动作，不只写招式名。被控制的肢体不能同时完成冲突动作；松脱、换向、起身和转身要有过程。

### 物理约束

- 支撑脚和重心支持当前攻击方向。
- 受击方向、身体位移和脚下摩擦保持一致。
- 贴身动作看清双方前臂、手腕和接触点。
- 大幅摔投、翻滚和腾空保留完整身体路径。
- 没有用户设定时不补拳种、摔法、伤势、骨折或致命结果。

### 兵器招式

每次兵器动作写清持握手、兵器部位、攻击线路、距离变化、接触反馈、受力方向和收回状态。

### 基本顺序

`持械状态 → 起手与步法 → 兵器线路 → 接触、格挡或落空 → 兵器与身体反馈 → 收势、换位或追击`

刃器表现刃线和切割接触，长柄表现距离与转向惯性，钝器表现重量与形变，远程器械表现瞄准、弹道、遮挡和后坐。换手、脱手、损坏、收回和再次拿起必须有可见过程。

### 连续约束

- 同一兵器跨镜头保持类型、数量、尺寸、持握手和状态一致。
- 兵器碰撞写出接触部位、弹开、滑开、摩擦或震颤。
- 没有用户指定时不增加武器、弹药、护具或变形。
- 兵器名称不自动生成喊招台词，也不自动决定胜负。

### 位移与轻功

位移必须说明动力、支点、方向、路径、速度变化和落点。

### 可用动力

蹬地、借墙、借栏杆、借树木、跳跃、滑行、坠落、被击飞、抓握摆荡和用户明确设定的飞行或瞬移。

### 执行约束

- 没有飞行或瞬移设定时，不写踏空、悬停和瞬间换位。
- 轻巧角色可用折身、翻转、滑步和借力改变方向；厚重角色用冲撞、惯性、制动和环境破坏表现重量。
- 运动结束必须落到支撑、悬挂、滑行、坠落、受击或继续移动中的一种状态。
- 位移不能跳过攻击接触、落地、撞击和恢复过程。

### 能力与法术招式

能力必须按实际条件落地，不能只写颜色、光柱、爆炸或冲击波。

### 基本顺序

`触发前置 → 产生部位或媒介 → 聚集或启动 → 传播线路 → 作用对象 → 接触结果 → 终止或残留`

前置可以是姿态、兵器、受击、场地、距离、蓄力或用户明确指定的条件。缺少前置时不跳过，不用特效替代动作。

### 约束

- 能力只归属于用户指定的角色、兵器或媒介。
- 能量形体、召唤物、法相和分身保持独立的控制、支撑和受力关系。
- 命中、落空、格挡和偏转分别写出，不因特效强度自动判定命中。
- 作用范围、持续时间、伤势、环境破坏和结局只按用户要求执行。
- 能力结束后写清消散、回流、残留或下一招条件。

### 发动条件必须说清楚

- 能力的发动条件如果不在用户已给的信息里，必须显式说明「需要先补哪一项」，并给出可创造条件、可替代条件、放弃该能力三个选项，由用户选；不自己替角色补一个法器、媒介、血契、身体结构或科技装备然后当作前提。
- 二级条件（法器、介质、气血、状态、场地、天气、特定动作接口）只用来判断这个能力此刻能不能发动，不写进动作本身的描述里去替代动作。
- 能力只负责「机制」这一段：前置、发动、作用、终止。至于谁怎么抬手、怎么站、怎么接住反噬、受击后身体怎么走，一律回到对应的徒手、兵器或位移模块处理，不用特效文字顶替身体路径。

### 武戏分镜索引

根据用户选择只读取一种主分镜模块；多人交锋可叠加多人模块，续接可叠加续接模块。

| 分镜选择 | 模块 |
| --- | --- |
| 单镜完成 | single.md |
| 多镜连续 | sequence.md |
| 续接上一段 | continuation.md |
| 多人交锋 | multi.md |

所有分镜都遵循：每镜一个主要观察目标，前镜末态是后镜起点，关键接触点、支撑、兵器路径和受力方向可见；景别与运镜遵循 镜头语言。

### 单镜武戏

单镜必须容纳完整的起势、接触或落空、对手响应、受力和结束状态。先确定镜头能看清的主要交锋，再选择景别和运镜。

人物保持近距、清晰、可辨；优先紧凑双人近景，并用手、脚、兵器和接触点特写补充动作因果。中景仅在确需同时读清双方位置和动作时短暂使用，不使用远景或大全景。运镜规则按 镜头语言 执行；一次运镜只服务一个观察目标，不用抖动、慢动作或特效遮挡动作链。

单镜结束时明确角色位置、朝向、持物、受力和下一段可承接状态。

### 多镜连续武戏

先完成招式序列，再按真实动作节点分镜。切镜可以改变观察角度，不能重置位置、方向、持物、伤势、速度或能力状态。

每镜记录：景别、机位、运镜、主要主体、当前招式、接触点、结束姿态和下一镜起点。完整动作不能被拆成无因的重复攻击；同一招只表现一次。

前镜没有完成的动作，后镜从其实际中间状态继续；前镜已经完成的动作，后镜不重演。

### 续接武戏

续接段先承接上一段的末态：位置、朝向、速度、高度、支撑、持物、受力、伤势、能力残留和环境运动。

本段时间从 `00:00.000` 重新计算，但不重复上一段动作。重叠区只写承接状态，新招式、位移和台词从本段指定起点开始。段末保持用户要求的继续、脱离、停战或终止状态。

续接段不自动改成首尾帧路线，也不添加新的角色、武器、能力或胜负。

### 多人武戏分镜

先划分主交锋和次交锋，再为每个主体记录位置、朝向、速度、高度、持物和受力状态。焦点可以切换，但非焦点主体不能无故消失或冻结。

- 主交锋完整表现起势、接触、响应、结果和下一状态。
- 次交锋只写用户要求或会改变主交锋的动作。
- 每轮至少改变位置、朝向、速度、高度、姿态、攻防关系、装备状态或环境状态中的一项。
- 第三方加入、换目标、误伤、溅射和退场都要有动作过程。
- 不重复相同招式、攻击线路、受击方向、击飞结果、构图或运镜。
- 每个主体在本段结束时分别落到继续交锋、失去战力、撤离、倒地或用户指定的最终状态。
