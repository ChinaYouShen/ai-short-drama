# 能力与法术招式

能力必须按实际条件落地，不能只写颜色、光柱、爆炸或冲击波。

## 基本顺序

`触发前置 → 产生部位或媒介 → 聚集或启动 → 传播线路 → 作用对象 → 接触结果 → 终止或残留`

前置可以是姿态、兵器、受击、场地、距离、蓄力或用户明确指定的条件。缺少前置时不跳过，不用特效替代动作。

## 约束

- 能力只归属于用户指定的角色、兵器或媒介。
- 能量形体、召唤物、法相和分身保持独立的控制、支撑和受力关系。
- 命中、落空、格挡和偏转分别写出，不因特效强度自动判定命中。
- 作用范围、持续时间、伤势、环境破坏和结局只按用户要求执行。
- 能力结束后写清消散、回流、残留或下一招条件。

## 发动条件必须说清楚

- 能力的发动条件如果不在用户已给的信息里，必须显式说明「需要先补哪一项」，并给出可创造条件、可替代条件、放弃该能力三个选项，由用户选；不自己替角色补一个法器、媒介、血契、身体结构或科技装备然后当作前提。
- 二级条件（法器、介质、气血、状态、场地、天气、特定动作接口）只用来判断这个能力此刻能不能发动，不写进动作本身的描述里去替代动作。
- 能力只负责「机制」这一段：前置、发动、作用、终止。至于谁怎么抬手、怎么站、怎么接住反噬、受击后身体怎么走，一律回到对应的徒手、兵器或位移模块处理，不用特效文字顶替身体路径。
