# 招式模块索引

只读取用户选择的动作载体模块。混合载体只加载实际参与本段的模块，不加载全部模块。

| 动作载体 | 模块 | 核心字段 |
| --- | --- | --- |
| 徒手 | [unarmed.md](unarmed.md) | 站姿、支撑、出手、接触、回收 |
| 兵器 | [weapon.md](weapon.md) | 握持、兵器部位、线路、接触、收回 |
| 能力 | [ability.md](ability.md) | 前置、产生、传播、作用、终止 |
| 位移或轻功 | [movement.md](movement.md) | 动力、支点、路径、落点、承接 |

每个模块只负责动作执行，不负责分镜字段、声音字段或其他模块的动作。招式序列统一由 [../flow.md](../flow.md) 管理。

## 选定前的可执行性核对

写入分镜前，先对每一个准备使用的招式逐条过一遍，有一项明显不成立就换动作或说明冲突，不硬写：

1. **能力匹配**：这个角色会这个招式吗？不会就要有学会、借力或临时爆发的可见理由。
2. **器械与肢体的兼容**：兵器形制、长度、双手或单手、以及角色的身体条件（身高、伤残、年龄）能不能支撑这个动作。
3. **入口姿态**：能不能从上一动作结束时的姿态直接进入？需要先撤步、收兵、换手或起身时，把这段过程写出来。
4. **空间条件**：当前场景有没有这个动作需要的距离、支撑点、落点、遮挡物和可破坏物；没有就换招或换位置。
5. **时长余量**：在用户给定的时长内，起势、接触、受力反馈和结果这四段放得下吗；放不下先报告，请用户选择缩短、拆分或换招。
6. **红线一致**：有没有违背用户锁定的动作顺序、胜负、禁用动作或写实程度；发现冲突就回到用户确认，不为保留招式去改剧情。

核对通过后，再把身体路径、接触部位和结果写具体；核对不通过时，宁可换一个更朴素但成立的动作，也不用看起来花哨却进不去、接不上的招式。
