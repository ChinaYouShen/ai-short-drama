# MiniMax H3 路线与输出格式

## 路线判定

| 用户选择 | H3 路线 | 参考素材在时间轴上的作用 |
| --- | --- | --- |
| 文生视频 | T2VA | 没有作为依据的图、视频或音频，完整视听时间线由文字建立 |
| 图生视频·首帧 | I2VA | `<Picture 1>` 是 0.00 秒的硬首帧，后续动作从该画面自然开始 |
| 图生视频·尾帧 | L2VA | `<Picture 1>` 是视频结束时的硬尾帧，前段动作逐步收束到该画面 |
| 图生视频·首尾帧 | FL2VA | 首图锚定开始，尾图锚定结束，中间描述连续的状态变化路径 |
| 多参考生成 | Ref2VA | 图片、视频、音频分别提供身份、场景、动作、镜头、声音或风格依据 |
| 视频续接或编辑 | Ref2VA 或平台对应参考任务 | 视频本身被继续、修改或仅作参考，必须在 `summary` 中说明真实关系 |

若上游分镜对象使用 `t2v`、`i2v`、`l2v`、`fl2v`、`r2v`，分别映射到文生、首帧图生、尾帧图生、首尾帧图生和多参考生成。平台没有尾帧按钮时，不把 `l2v` 静默改成首尾帧。

首帧、尾帧和首尾帧是硬约束；普通人物图、风格图、动作参考视频和音色参考音频不是硬帧。用户说“参考这张图”时先确认它是硬帧还是普通参考，不能凭词语猜测。

## 结构化镜头输入

当上游已经提供分镜对象时，使用以下字段作为输入：

```text
mode: t2v | i2v | l2v | fl2v | r2v
beats: [{ start, end, text }]
durationSec: number
size: 景别
camera: 运镜
continuity: 衔接说明
linkPrev: boolean
dialogue: 原文对白
soundscape: 全程环境声
references: 按用户顺序排列的图、视频、音频清单
```

`beats`、`durationSec`、景别、运镜和衔接属于已确认的分镜设定。视频提示词负责把它们扩写成可执行描述，不负责重新拆镜或改变这些字段。`mode` 是可选路线；用户跳过时，不强制追问，不生成虚构的硬帧或素材标签，先交付不依赖路线的提示词正文。只有用户要求的输出格式无法脱离路线完成时，才询问该路线。

所有文戏和武戏镜头都读取 [cinematography.md](cinematography.md)。有角色出镜时使用近距构图，限制中景，禁止远景和大全景。

## 基础路线字段

T2VA、I2VA、L2VA、FL2VA 使用下面三个字段，字段顺序固定：

```text
integrated_multimodal_description:
[Shot 1] ...

overall_soundscape:
...

non_diegetic_music:
...
```

`integrated_multimodal_description` 沿时间顺序写视觉、主体、动作、表演、镜头、对白和镜头内声音。首帧路线在 `[Shot 1]` 开头说明它承接 `<Picture 1>`；尾帧路线在最后一个镜头明确落到图片状态；首尾帧路线说明首图、连续变化和尾图三者关系。

结构化结果中，`integrated_multimodal_description` 第一项只含整体风格，后续每项对应一个 `beats` 时间段，并包含 `shot`、`start`、`end`、`text`。最终 `prompt` 只由字段名、风格句、时间段正文和声音字段拼成，不包含 Markdown 标题或解释。

三种图生路线的开头或结尾约束分别是：

- I2VA：第一句说明 `<Picture 1>` 在 0.00 秒被完整承接，然后从图片中的姿态、构图、光线和道具继续发展。
- L2VA：最后一个镜头说明在视频结束时逐步收束到 `<Picture 1>` 的姿态、构图、光线和道具；不要把尾图误放成开场。
- FL2VA：说明 `<Picture 1>` 对齐 0.00 秒、`<Picture 2>` 对齐视频末秒，并描述两张图之间可执行的连续动作路径；除非用户明确要求，多数情况下使用一个连续镜头。

没有实际切镜时只写连续的 `[Shot 1]`，不为了套格式制造切点。确有切镜时，后续镜头使用递增时间，例如 `[Shot 2] At 00:04.200, the camera cuts to ...`。切点必须服务于新信息，轻微改变景别或角度优先用镜头运动表达。

基础路线中的主体可以用稳定的角色名称或 `Subject` 说明，但只有 Ref2VA 需要完整的参考标签和保留分析。

### 时间码契约

提示词里每个 `At` 后的时间码只有一种合法写法：`mm:ss.mmm`，两位分、两位秒、三位毫秒。`00:1.200`、`00:001.200`、`00:03850` 都是错的，模型侧解析会失败或错位。

- 第一镜从 `00:00.000` 起写；也可以不写，此时第一个 `At` 代表第二镜的起点。
- 时间码必须严格递增，相邻两镜的差值就是镜长，必须落在 2～5 秒。
- 一个连续镜头不拆时间码；只有真硬切才增加 `[Shot N]` 与新的 `At`。
- 单段上限 15 秒（`SEGMENT_MAX_SECONDS`），**动作时长与台词时长合计算**，不是只算台词。
- 因此每段正文必须能核对总时长：在风格句处写「本段总长约 X 秒」，一段一句；多段输出时每段各写一次，各自 ≤15 秒。
- 超过 15 秒一律拆段，不靠删动作或加快语速硬塞：按「连续剧情多段输出」的规则承接，段末写稳定交接姿态，下一段从 `00:00.000` 重算。
- 最后一镜的结束点不写时间码，由「本段总长约 X 秒」与镜长共同约束。
- 四段结构（起势／宣言／爆发／收束）是时间预算，不是镜头数；段长不足 2 秒要与相邻段同镜，不切碎镜。
- 多段输出时每段各自从 `00:00.000` 重算，镜号也从 1 重起；这不是时间码倒退，脚本按段判。全篇只做一次递增判断会误报。
- 首镜可以不写 `At`（默认 `00:00.000`）；此时第一个 `At` 是第二镜起点，镜长按相邻切点连差推算，不从 0 秒重算。
- 切段只认正文时间线字段（`integrated_multimodal_description`／`detailed_description`／`详细描述`）。中文六段的 `主体定义`／`摘要`／`保留分析` 是段头，不构成新段起点；只有本段已经写完一次正文时间线，后续再出现正文字段才算下一段。



基础路线正文默认使用用户指定语言；用户未指定时跟随用户输入语言。Ref2VA 六段结构默认使用英文正文以贴合通用接口格式，只有对白、歌词和画面文字保留原语言；用户明确选择中文时，六段标题和正文全部使用简体中文，技术标签、关系标记和 `<d>` 语言码保持英文。用户明确选择其他语言时按用户要求输出，不因翻译改写台词。

中文六段标题固定为 `主体定义:`、`摘要:`、`保留分析:`、`详细描述:`、`整体声景:`、`非叙事配乐:`；英文六段标题使用对应英文键。结构化对象字段始终使用英文键，避免不同 Agent 解析失败。

## 多参考路线六段结构

Ref2VA 使用以下六个字段，字段名和顺序固定：

```text
subject_definitions:
...

summary:
...

retention_analysis:
...

detailed_description:
...

overall_soundscape:
...

non_diegetic_music:
...
```

### `subject_definitions`

为实际会进入成片或实际被引用的内容建立稳定标签：

- `<Subject N>`：人物、群体、道具、场景、服装、动作、姿态或视觉风格。
- `<Picture N>`：实际承担首帧、尾帧、关键帧、分镜构图或时间轴锚点的图片。
- `<Video N>`：被编辑、续接，或提供完整剪辑结构、节奏和镜头运动的视频。
- `<Audio N>`：被复制或参考的音频、音乐、音色、对白、歌词或声音质感。

每个标签只表示一个稳定含义，跨 `summary`、`retention_analysis`、`detailed_description` 和声音字段保持不变。一个素材可以提供多个主体，一个主体也可以由多个素材共同定义；只在实际使用时建立标签。

`<Subject N>` 只给**实际进入成片的对象**：人物、群体、道具、场景、服装、动作、姿态，或有素材支撑的视觉风格。「气质基调、光效语言、色彩倾向」这类没有对象承载的风格描述**不单独建号**——它没有主体，成片里也没有可指的实体，编号会凭空多出一号并让 `retention_analysis` 多出一行空账。风格写进 `summary` 一句，或写进 `detailed_description` 首句。只有用户真的挂了一张风格参考图、并要求锁定它的观感时，才把它登记为 `<Subject N>` 并在保留分析里标 `weak_reference`。

如果上游给出了参考素材清单，图片、视频和音频标签必须按清单顺序生成，数量不能少于清单中的实际引用，也不能凭空补号。图像类别固定为 `character`、`scene`、`prop`、`standing` 或 `reference`；视频使用 `<Video N>`，音频使用 `<Audio N>`。角色、场景、道具和站位的锁定范围不能互相替换。

#### 编号三套独立，绑定必须写明

`<Subject N>`、`<Picture N>`、`<Audio N>` 是三套互相独立的编号，不共用序号，也不默认一一对应。三张图两个角色、两个音色一个角色都是常态。

- **每个角色或主体都必须写清它用哪张图、哪段音频**，例如「月光（`<Subject 1>`）取 `<Picture 2>` 的外形、`<Audio 1>` 的音色」；不许因为「看起来是第一个」就默认配对。
- 编号一经按素材清单建立，全篇锁定：不中途改号、不重排、不在后文新增未登记的编号。
- 没有绑定音频的角色不写 `<Audio N>`；没有提供图片的主体不当作图像引用；用户只给了一张图时不推断还有别的图。
- 同一素材支撑多个角色或同一角色由多张图共同定义时，把关系逐条写出，而不是靠编号顺序暗示。

### `summary`

用一个短段落说明任务和参考关系。按实际情况在开头使用以下任务类型并用 ` + ` 连接：

- `keyframe completion`
- `reference generation`
- `video editing`
- `video continuation`
- `audio reuse`
- `audio reference`

普通视频只提供镜头或动作参考时使用 `reference generation`；只有视频被直接改写才用 `video editing`；只有新内容从源视频末态继续才用 `video continuation`。原音轨完整沿用才用 `audio reuse`，只模仿音色、节奏或声音质感用 `audio reference`。

### `retention_analysis`

一行对应一个已定义标签，说明它出现在哪些镜头及其保留关系。可视内容使用：

- `fully_preserved`
- `partially_preserved`
- `attribute_transfer`
- `weak_reference`

音频使用：

- `fully_copy`
- `partially_copy`
- `reference`
- `weak_reference`

关系描述必须与 `subject_definitions` 中的用途一致。新增剧情不算参考丢失；只有参考内容本身的使用方式发生变化才改变保留标记。

### `detailed_description`

先写整体视觉、空间和参考作用，再按播放顺序写镜头。每镜交代主体位置、动作或表演、镜头运动、状态变化和当前声音，并在第一次实际使用时插入对应参考标签。

连续镜头段仍只输出一个 `[Shot 1]`，本段时间从 `00:00.000` 重新计算；开头必须承接上一段末态并明确无硬切，结尾落在稳定交接姿态。只有确实发生硬切时才增加新的镜头编号。

## 连续剧情多段输出

用户明确要求把一条连续剧情拆成多段时，可以输出公共主体定义加多组提示词：

- 公共主体定义只锁一次身份、服装和长期参考关系。
- 每组只写当前段的摘要、保留分析、详细描述、整体声景和非叙事配乐；不重复建立角色档案。
- 第 2 组起保持同一空间、主体和配乐主题，详细描述首句写无硬切承接上一组。
- 每组时间从 `00:00.000` 重新起算，段末写稳定交接姿态；最后一组才收束动作或配乐。
- 用户选择严格改写时，只按用户给出的每段内容；选择允许扩写时，才补足段内镜头、声画和衔接细节。

## 台词、文字与声音

- **视频提示词正文不写角色姓名**：用通用身份指代（「一名铁灰长衫的中年男子」「对座的年轻女子」），姓名只允许出现在台词原文里。这是 H3 与同类视频模型的通行规范，不跟着提示词语言变。
- **分镜图提示词反过来要直呼其名**：那一侧的名字指向挂上去的那张角色设定图，用名字才能把图和人对上；两侧规矩不同，不要互相搬运。

- 说话者按首次发声顺序分配 `(S1)`、`(S2)`；同一人跨镜头沿用原编号。
- 说话者的身份、声线、语速和发声位置写在 `<d>` 外，实际台词只放进 `<d>[语言] 原文</d>`。
- 画外音使用 `says in an off-screen voiceover` 的语义，并紧跟说明画面内人物嘴唇保持闭合。
- 同一句话跨切镜时标出连续关系并使用 `<scenetrans>`；只有视频结尾确实截断发言时才用 `<cutoff>`。
- 台词、动作声和镜头内音乐写入当前镜头；连续环境声写入 `overall_soundscape`；角色听不到的配乐写入 `non_diegetic_music`。
- 画面中必须存在的字幕、招牌、界面或物件文字用双引号，并保持原始语言和标点。
- 分镜图提示词若被要求输出，应作为单独的 `framePrompt` 字段，只描述一个静帧，不写 H3 段名、时间轴或连续运镜。

## 参数与能力边界

官方 H3 文档的公开能力、输入数量、时长、比例、分辨率和平台按钮会更新。技能只根据用户当前选择生成结构，不把某次产品配置写成永远有效的保证。需要给出实际上传数量、API 参数或部署命令时，先以当前官方文档或用户界面为准。
