# 故事大纲

## 可执行任务

- 从选题或用户概念建立完整大纲。
- 只生成大纲骨架、故事线、角色名单、三幕结构、节奏、结局或分集摘要。
- 只补充新增分集或分集看点。
- 从已有原文拆出大纲。
- 检查大纲字段、人物、集数、因果和结局是否完整。

## 执行规则

- 只写用户选择的部分；跳过角色、三幕、节奏或分集时不强行补齐。
- 需要完整大纲时，按“角色功能 → 时空规则 → 核心冲突 → 故事线 → 三幕转折 → 节奏波形 → 情绪锚点 → 结局 → 分集摘要 → 卡点”组织。
- 角色至少说明姓名、功能和一句定位；长画像留给人物卡。
节奏量化口径（前 3 秒、三段结构、爽点密度、集末留扣）见 [rhythm.md](rhythm.md)。

- 每集摘要和看点分开写，集号连续；- 多集时每集摘要末尾补一句「本集钩子：…；断章点：…」，钩子和断章的位置按本文件「多集长剧的结构量化」检查。
只补集数时保留已有集标题和摘要。
- 从原文拆解时按原文情节和章节计算集数，不凭固定集数填充；未完结文本不强行写成确定结局。
- 因果必须闭合，人物目标、阻力、转折和结果互相对应；没有原文依据的身份、秘密、反转和结局不新增。
- 用户指定 `strict` 时只整理已给事实；指定 `expand` 时只补授权范围内的结构表达，不新增角色或剧情结果。

## 多集长剧的结构量化

只在做多集短剧（一般 20 集以上）时生效；单集或短片不套这些数。这些是长剧的工程参数，用来防止注水和节奏塌陷：

- **钩子**落在全集最前面 3 个节拍内，而且要带动作，不能只靠一句台词或环境描写。
- **爽点间隔不超过 3 集**：连续三集没有兑现任何爽点，观众就流失了；爽点可以是打脸、揭秘、反转、升级、亲密关系的推进。
- **断章断在「反击前 0.5 秒」**：把集尾停在主角即将出手、真相即将说破的那一刻；禁止断在爽完之后——爽完断章等于把观众的下一集理由用完了。
- **付费墙之后的下一集，前 15 秒必须兑现承诺**：付费用户买的是「马上要发生的事」，第一集就兑不了现，退款和差评都在这时候来。
- **四幕占比约 20 / 35 / 25 / 20**（起势 / 对抗 / 转折 / 收束）；某一段明显超出时，先查是不是在写无效对话。
- **主线场景数量上限 = 4 + ⌈集数/10⌉，并夹在 5～15 之间**（60 集给 10 个）；超过就合并场景，不靠新增布景撑时长。
- 角色档位：主角组 ≤5、重要配角 ≤10、功能性角色 ≤10；叙事道具 ≤8 件。超过就合并次要角色，或把道具功能并给已有道具。

以上为长篇时的建议阈值，用户已有明确设定时以用户为准；改动会压缩用户已定的角色或场景时，先报冲突再动手。

## 交付

默认返回可读大纲。用户要求程序载荷时使用 `characters`、`setting`、`storyline`、`acts`、`rhythm`、`endingDesign`、`episodes` 等字段；未选择的字段不输出或保持原值。
